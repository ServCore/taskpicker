# 通用表格接入方案

状态：设计方案，尚未实现。

## 目标与边界

每份文档通过配置接入统一任务系统，不为每张表生成 Go 代码或专用结构体。任意列都能作为筛选字段，负责人没有特殊必填地位。项目仍负责管理文档、本地目录和项目日报；字段映射、拉取条件、完成状态规则按文档的工作表保存。

第一版继续支持现有腾讯普通表格、智能表格和 Excel 读取。表格需具有可确定的表头和一行一条记录的结构。多层交叉表、跨行拼装任务、未知字段类型和新增文档平台不属于此次承诺；AI 识别配置不能代替数据解析或账号权限。

## 现状与需要一起调整的环节

- 表头通过负责人列定位，读取接口强制填写姓名；Excel 有同样约束。
- 前端标题、状态、备注、日期和优先级主要按预设列名识别。
- 状态与备注写入、撤销、回写、日报活动均重复使用上述识别规则。
- 回写身份核对强制包含任务内容与负责人。
- 旧文档键初始由链接与负责人计算；普通表格的执行历史还使用行号作为身份的一部分。

因此此次应建立共享的配置和解析结果，覆盖同步、展示、编辑、日报与执行上下文，不能仅取消姓名输入校验。

## 统一配置

### 来源与列结构

先读取来源结构，再决定如何筛选任务：

1. 获取文档与工作表清单，链接指定的工作表作为默认选择。
2. 智能表使用字段 ID、字段类型、可选值与记录 ID；普通表格、Excel 支持预览并指定表头行。
3. 重名或空白列通过列字母或位置辅助区分，不能只凭名字绑定。
4. 保存结构指纹，以便后续同步发现列增删、改名和类型变化。

结构探测不以负责人或已有任务映射为前提，也不在预览时把文档加入正式任务库。首次先展示有限行样例；精确匹配总数需要完整扫描，完成前展示“样例命中”而非全表数量。图片只在条件通过后下载。

### 字段用途

| 软件用途 | 配置方式 | 缺失时行为 |
| --- | --- | --- |
| 任务内容 | 必选一个内容列 | 不能完成正式接入；空白内容行不作为任务 |
| 标题、模块 | 可选 | 从任务内容生成列表摘要 |
| 状态 | 可选一个列 | 展示“未设置状态”，不显示状态编辑控件 |
| 备注 | 可选多列 | 不显示备注编辑控件 |
| 截止日期 | 可选 | 不参与今日截止提醒 |
| 优先级 | 可选 | 不展示优先级标签 |
| 负责人 | 普通的可选展示字段 | 不影响接入、筛选与回写资格 |
| 唯一业务编号 | 可选；需校验非空且唯一 | 用于辅助普通表格任务身份匹配 |

映射之外的原始列继续保留，可搜索、查看详情，也可参与筛选。没有映射为用途的列不因此丢弃。所有消费者使用同一份映射后的任务视图，避免列表与回写识别不同的状态列。

没有状态列时，未完成范围不执行状态排除，并明确说明；仍可查看任务、记入日报、手动执行 AI 任务。仅有备注映射时，支持单独保存和回写备注，不能因缺少状态列而阻止。只允许按远程类型支持的方式编辑状态与备注，其他列第一版不提供任意回写。

### 拉取条件

所有已解析列均可选择。按字段类型提供条件：

- 文本：等于、不等于、包含、不包含、为空、不为空。
- 人员、多选：包含任一所选项、包含全部所选项、不包含所选项、为空、不为空。按成员匹配，避免姓名子串误命中。
- 枚举：属于、不属于若干选项、为空、不为空。
- 数字：等于、大于、小于、区间、为空、不为空。
- 日期：早于、晚于、区间、今天、为空、不为空。相对日期在每次同步开始时按本机日期解析，整轮保持一致。
- 其他暂不具备类型解析能力的字段：可对已解析展示文本筛选，界面标明使用文本规则，不假装按原生类型比较。

第一版采用一个平铺条件组，可选择“全部满足”或“任一满足”，不做嵌套条件树。零个条件表示不增加自定义限制。字段缺失或配置失效属于配置错误，不能按空值处理、静默放行。

“默认只同步未完成”独立于自定义条件：

`最终范围 = 自定义条件结果 AND 完成状态范围`

状态范围默认排除已配置的完成值；支持切换为全部状态。完成值按每份文档配置，智能表优先提供实际枚举选项，普通表格允许按实际值选择或输入。现有结束状态词仅用于推荐初值。若筛选显式要求某个已完成状态而范围仍为未完成，预览中提示冲突并提供切换，不能暗中改规则。

例如：

```text
匹配方式：全部满足
模块        等于        登录
优先级      属于        紧急、高
任务范围：未完成
```

负责人条件只有用户主动添加，或旧配置迁移时才出现。

## 界面流程

### 添加文档

`粘贴链接 → 读取结构 → 选择工作表/表头 → 配置字段用途与拉取条件 → 预览 → 添加并同步`

使用一个可分步的接入页面，复用项目选择、登录与取消能力。界面预填本地规则能识别的用途，保留修改入口；预览展示任务内容、状态、命中情况和结构警告。没有命中任务可以保存配置，不能报成解析失败。

### 已有文档

现有同步按钮旁的齿轮保留，进入该文档的配置页面，按“字段用途、拉取条件、完成状态”组织。保存后标明“下次同步生效”，可点击“保存并同步”立即应用。

保存的新配置先作为候选；拉取成功后，配置版本与新快照一起生效。失败时原快照继续携带其原配置版本，待生效配置单独保留，避免新映射错误解释旧缓存。涉及映射或拉取范围的调整，如有待回写修改，先解决待回写项目再应用。

列表顶部现有状态、搜索、“不查看”等继续作用于已同步内容；文档拉取条件决定获取哪些记录。界面分别说明作用范围，避免把本地隐藏误认为停止同步。

侧栏底部当前固定显示的负责人信息也需要改为文档配置摘要，不再默认补出姓名。项目层不提供隐含的全局负责人条件。

## AI 的位置

AI 是可选配置助手。没有 AI、模型不可用、返回内容无效时，仍能手动接入并正常同步。

第一版提供明确按钮“AI 识别字段”。默认使用现有 AI 连接配置，沿用地址、模型与 Key；表格识别使用独立的内置任务提示词，不使用日报提示词。

- 输入表头、字段类型与可选值；必要时允许用户选择少量样例辅助识别。
- 输出结构化的字段用途与完成状态建议，对拿不准的项目标记待确认。
- AI 可以解释“事项对应任务内容”“进度对应状态”，不能猜出用户是谁或擅自设置负责人条件。
- 程序校验字段引用、类型与规则合法性后再填入界面，用户预览确认后保存。
- 不生成和运行任意 Go、JavaScript、SQL 或每张表专属的解析代码。
- 平时同步直接执行保存的规则，不逐行调用模型，也不因失败自动扩大数据范围。

自然语言生成拉取条件可作为后续增强；第一版先把字段识别做完整，条件编辑器始终可手动使用。

## 回写、身份与历史

### 文档与任务身份

- 已有文档键原样保留，不能因负责人条件移除或修改筛选而重算。
- 新接入使用独立稳定的文档绑定 ID，来源地址与配置作为属性保存。
- 智能表使用工作表 ID + 记录 ID 定位任务，使用字段 ID 绑定列；标题变化不创建新任务。
- 普通表格优先使用经校验唯一的业务编号辅助匹配；没有时仍核对原行和任务快照，不单凭相似标题自动认领移动后的记录。
- 建立可持久化的本地任务 ID，执行记录和日报引用它。旧 ID 建立兼容映射；不能可靠匹配时保留旧历史并提示核对，不能把历史接到疑似相同的另一行。
- 因筛选改变而不再同步的任务，缓存中可标记为不在当前范围，操作历史、执行工作区和 Markdown 文档继续保留。

普通表格在没有稳定业务编号且发生插行、重排时，无法保证自动恢复任务身份，这是来源能力的边界。

### 写入核对

筛选字段用于决定拉取范围，不等同于任务身份，也不自动赋予编辑权限。写回使用已确认映射，定位并核对远程记录及待改字段原值；负责人不是必需核对项。

智能表以记录 ID 为主；普通表以唯一编号或原行快照校验为主。目标不唯一、字段引用失效、类型变更、公式列和原值冲突时，停止回写并保留本地修改。保留逐字段回读、部分成功重试及状态栏静默同步行为。

因本地修改状态而离开拉取范围的任务，在远程回读确认前仍保留于待同步队列；完成后才按条件移出当前列表。

## 结构变化与升级兼容

智能表字段重排依靠字段 ID 继续识别；稳定 ID 未变的改名可更新展示名，类型变化需重新校验。普通表列移动或改名只能在唯一、可核对时重新关联；重名、丢列或歧义时提示修复。新增不相关的列不要求重配，原始列继续保留。

旧文档首次升级生成等价配置：

1. 原负责人姓名转换为对应列的成员匹配条件，保留多人单元格语义。
2. 原“包含已完成”转换为完成状态范围，保持现有结果。
3. 按当前映射规则生成字段用途，并固定到该文档配置。
4. 保留文档键、项目归属、历史、草稿、执行记录、原文件和回退备份。

迁移可重复执行且不会重复创建数据。失败时不覆盖旧配置，也不能默认清空条件或扩大同步范围。

## 模块安排

沿用本次整理的目录边界：

```text
desktop/internal/
  reader/       读取原始结构与数据，保留来源定位信息
  document/     配置校验、字段解析、结构变更检测
  filter/       条件类型、规则校验、统一匹配引擎
  ai/           可复用的模型请求与结构化配置建议
  model/        共享配置、列引用与任务身份类型
  app/          桌面接口和同步/回写/日报/执行的协调
frontend/src/features/
  documents/    接入页面、字段映射、条件编辑、预览
```

独立规则引擎由在线读取与 Excel 共用；前端展示、活动记录与回写使用统一解析结果。模型凭据保持后端保管，不传给前端。具体文件随实现拆分，不再把新增文档编辑逻辑放入大型 App.vue。

## 实施顺序

1. **通用接入基础**：结构探测、手动表头、字段映射、类型筛选与预览；同步入口去除负责人必填。
2. **业务闭环与迁移**：统一列表、完成规则、状态/备注回写、日报、任务身份与执行历史；完成旧配置升级和结构变化处理。第 1、2 步作为同一批可发布功能，不能只交付“新表能读”。
3. **AI 辅助识别**：复用 AI 连接，增加结构化建议、待确认项、失败回退与用户确认。自然语言条件配置后续再扩展。

## 验收重点

- 没有负责人列的新表可以接入；有负责人列也不强制筛选。
- 任意支持解析的列可以添加条件，全部/任一、空值、多人、多选、数字与日期的语义正确。
- 不设置自定义条件时仍默认排除配置的已完成状态；没有状态列时有明确说明。
- 自定义列名可以展示、记入日报、执行任务和按类型回写状态/备注；没有状态列也可只写备注。
- 预览、首次同步、启动同步、Excel 使用一致的映射与匹配规则；读取失败不覆盖缓存。
- 同名任务、重复业务编号、插行、列重排、类型变化和回写冲突不会导致写错记录或串联执行历史。
- 筛选变化、任务完成、项目移动和应用重启不丢日报、历史日志或工作区；待回写记录不被过滤掉。
- 两份既有文档升级后筛选结果保持一致，凭据不被迁移或覆盖。
- AI 缺席、超时、返回不存在的字段或非法配置时，手动配置与既有同步照常可用。
- 使用本次给出的无负责人表验证读取与预览；远程写入验证使用专门测试文档或另行明确指定的测试记录。
